## Шаг 1. Секонд-симка

Не основной номер. Не корпоративный. Не симка партнёра или ребёнка.

Что подходит:
- любой оператор РФ, eSIM или физическая,
- регистрация на ваш паспорт (важно для верификации в случае спора),
- отдельная от основной коммуникации.

Что не подходит:
- симки в чужом имени,
- виртуальные номера сервисов для приёма SMS (banned MAX-эвристикой за минуту, аккаунт улетит в флаг),
- номера из стран, не поддерживаемых MAX на момент написания.

Стоимость симки в 200-500 ₽. Это плата за разделение рисков. Если когда-нибудь придёт претензия от платформы или регулятора, у вас будет основной номер для общения и второй для эксперимента.

Установите MAX-app на любом устройстве (можно эмулятор), активируйте секонд-симку, дайте аккаунту нормальное имя. Не «testbot» и не «АИ-помощник»: такие имена сразу привлекают внимание антибот-эвристики. Имя должно выглядеть как обычный пользователь.

Опционально: загрузите аватарку, заполните био. Пустой аккаунт без аватара и био это флаг автомата.

## Шаг 2. (Опционально) Регистрация Bot API

Только если у вас есть юрлицо РФ или ИП-резидент. Если нет, пропускайте этот шаг и идите к Шагу 3.

1. Откройте `business.max.ru`, верифицируйте организацию (до 48 часов).
2. Создайте бота через раздел «Чат-боты». Имя на латинице или кириллице, 1-59 символов. Никнейм генерится автоматически как `idИНН_bot`.
3. Загрузите логотип (500x500, до 5 МБ), описание (до 200 символов).
4. Отправьте на модерацию (до 48 часов).
5. Получите токен в личном кабинете.

Документация: [dev.max.ru/docs-api](https://dev.max.ru/docs-api). Официальные SDK в README.

После получения токена сохраните его:

```bash
mkdir -p ~/.config/clawbot-max
echo "<bot-token>" > ~/.config/clawbot-max/bot-token.txt
chmod 600 ~/.config/clawbot-max/bot-token.txt
```

Это бот, который будет вашим личным «командным центром». Сюда вы пишете команды, сюда же listener дублирует переписку с собеседниками.

Если юрлица нет, можно обойтись без Bot API. Тогда вместо дублирования в MAX-бот используйте email через msmtp, локальный лог-файл, или Telegram-бот через TG Bot API.

## Шаг 3. SMS-логин секонд-аккаунта в User API

Цель: получить токен длительной авторизации для постоянного использования.

Идея: подключаемся к `api.oneme.ru:443`, делаем handshake, запрашиваем SMS, подтверждаем код, забираем токен.

В production советую использовать готовый flow из [vkmax](https://github.com/nsdkinx/vkmax), там есть `auth.py` с обработкой 2FA, флапов, ретраев. Я ниже покажу схему: какие опкоды, какие поля, что ловить.

### 3.1 Handshake (Op 6)

```python
import socket, ssl, struct, uuid, time
import msgpack

HOST = "api.oneme.ru"
PORT = 443
PROTO_VER = 10

def connect():
    ctx = ssl.create_default_context()
    sock = ctx.wrap_socket(socket.socket(socket.AF_INET), server_hostname=HOST)
    sock.connect((HOST, PORT))
    return sock

def send_packet(sock, opcode, payload, seq=1):
    body = msgpack.packb(payload, use_bin_type=False)
    header = struct.pack(">BBHHI", PROTO_VER, 0, seq, opcode, len(body))
    sock.sendall(header + body)

# deviceId: один раз сгенерить и сохранить. Не менять!
DEVICE_ID_PATH = "device_id.txt"
import os
if os.path.exists(DEVICE_ID_PATH):
    device_id = open(DEVICE_ID_PATH).read().strip()
else:
    device_id = str(uuid.uuid4())
    open(DEVICE_ID_PATH, "w").write(device_id)
    os.chmod(DEVICE_ID_PATH, 0o600)

sock = connect()
send_packet(sock, 6, {
    "userAgent": {
        "deviceType": "ANDROID",
        "locale": "ru_RU",
        "appVersion": "25.6.1",  # сверить с актуальным, см. APK на 4pda
    },
    "deviceId": device_id,
})
```

**Почему `deviceId` важен.** MAX-эвристика отслеживает «прыгающее устройство». Если у вас новый uuid каждый запуск, через несколько сессий сервер начнёт резать запросы. Сохраните один раз, не трогайте.

### 3.2 Запрос SMS (Op 17)

```python
phone = "+79..."  # ваш секонд-номер
send_packet(sock, 17, {"phone": phone, "type": "START_AUTH"})
```

В ответ должен прийти пакет с `cmd=1`. В payload-е будет `authToken` (временный) и `codeLength`.

### 3.3 Подтверждение кода (Op 18)

SMS придёт на секонд-симку, обычно 6 цифр.

```python
verify_code = input("SMS code: ")
send_packet(sock, 18, {
    "token": auth_token,  # из ответа Op 17
    "verifyCode": verify_code,
    "type": "CHECK_CODE",
})
```

Возможные исходы:
- `cmd=1` + long-term токен в ответе, успех,
- сервер возвращает `passwordChallenge`, на аккаунте 2FA, нужен Op 115 с паролем,
- `cmd=0` + ошибка, неверный код, истёк, лимит попыток.

### 3.4 Извлечение токена

Стандартный `msgpack.unpackb` часто не справляется с ответом MAX. Я использую regex по сырым байтам:

```python
import re
# Long-term токен это строка ~100-200 байт base64url-стиля
match = re.search(rb"[A-Za-z0-9_\-+.~=]{100,}", raw_response)
token = match.group(0).decode("ascii")

# Сохранили
with open(os.path.expanduser("~/.config/clawbot-max/token.txt"), "w") as f:
    f.write(token)
os.chmod(os.path.expanduser("~/.config/clawbot-max/token.txt"), 0o600)
```

Закрываем сокет. Дальше работаем с long-term токеном через Op 19 (LOGIN).

**Безопасность токена.** Этот токен полностью эквивалентен паролю аккаунта. Утечка = полный доступ к чатам и контактам. Никогда не коммитьте в репозиторий, не отправляйте в логах, не пишите в публичных каналах. `chmod 600` обязателен.

## Шаг 5. Listener: постоянный сокет с push-событиями

Цель: держать одну сессию, ловить входящие через op=128, прогонять через LLM, отвечать через op=64.

### 5.1 Перед запуском: Op 97

**КРИТИЧНО.** Один раз при первом запуске вызовите Op 97 (LOGOUT_OTHER_SESSIONS).

```python
send_packet(sock, 97, {"sessionIds": []})  # параметр игнорируется сервером
```

Это разлогинит **все** другие сессии аккаунта, **включая мобильный клиент**. Зачем: MAX доставляет push-события только одной активной сессии. Если параллельно работает мобильный клиент и Python-listener, push идёт случайной из двух. Обычно мобильному.

После Op 97 мобильный клиент попросит перелогиниться по SMS. Если вам он не нужен, не логиньтесь, просто закройте. Если нужен, залогиньтесь снова, но тогда push снова уйдёт ему, и listener будет молчать. Один-к-одному.

### 5.2 Login с interactive=True

```python
send_packet(sock, 19, {
    "token": long_term_token,
    "interactive": True,  # КРИТИЧНО, без этого push не приходит
    "chatsCount": 40,
    "chatsSync": 0,
    "contactsSync": 0,
    "presenceSync": 0,
    "draftsSync": 0,
})
```

После этого ваш сокет подписан на пуш. Будут прилетать опкоды 1 (keepalive), 128 (новое сообщение), 129 (уведомление про обновление чата), 130 (read receipt), 132 (presence).

### 5.3 Обработка op=128

В op=128 уже есть весь объект сообщения, отдельный fetch истории не нужен. Парсим sender и text по сырым байтам:

```python
import re

def parse_op128(raw: bytes):
    sender_match = re.search(rb"\xa6sender\xd2(.{4})", raw, re.DOTALL)
    sender = int.from_bytes(sender_match.group(1), "big", signed=True) if sender_match else None

    text_match = re.search(rb"\xa4text", raw)
    text = ""
    if text_match:
        i = text_match.end()
        if i < len(raw):
            b = raw[i]
            if 0xa0 <= b <= 0xbf:  # fixstr
                ln = b & 0x1f
                text = raw[i+1:i+1+ln].decode("utf-8", errors="replace")
            elif b == 0xd9 and i+1 < len(raw):  # str8
                ln = raw[i+1]
                text = raw[i+2:i+2+ln].decode("utf-8", errors="replace")
            elif b == 0xda and i+2 < len(raw):  # str16
                ln = int.from_bytes(raw[i+1:i+3], "big")
                text = raw[i+3:i+3+ln].decode("utf-8", errors="replace")
    return sender, text
```

`re.DOTALL` обязателен, без него точка не матчит \n, а int32-поле часто содержит этот байт.

### 5.4 Игнор собственного эха

Когда вы отправляете сообщение через op=64, MAX заодно пушит вам op=128 как «новое сообщение» с sender=вы сами. Не отвечайте на свои сообщения, иначе зациклитесь:

```python
SELF_USER_ID = <ваш user_id секонд-аккаунта>
if sender == SELF_USER_ID:
    continue
```

User_id секонд-аккаунта можно узнать через Op 16 (PROFILE) или вынуть из ответа на Op 19.

### 5.5 Backoff на разрывах

Сокет рвётся регулярно (VPN-блипы, ротация сервера). Exponential backoff обязателен:

```python
def main():
    backoff = 2
    while True:
        try:
            run_session(load_token())
        except KeyboardInterrupt:
            return
        except Exception as e:
            print(f"[listener] session died: {e!r}; reconnecting in {backoff}s")
            time.sleep(backoff)
            backoff = min(backoff * 2, 60)
```

Без логирования `Exception` через неделю проблема превратится в «бот молчит, не понимаю почему».

Полный listener в [examples/user_api_listener.py](examples/user_api_listener.py).

## Шаг 6. LLM-обвязка

Когда поймали op=128 с осмысленным текстом, прогоняем через LLM.

### 6.1 Выбор модели

- Reasoning-модели (Kimi K2.5, o1-стиль, R-стиль) «думают» в скрытом поле `reasoning`, которое жрёт ваш `max_tokens`. При лимите 400 reasoning съест все 400, до `content` дело не дойдёт, ответ вернётся пустым.
- Решения: или поднимите `max_tokens` до 2000+ (reasoning возьмёт 200-800, content успеет), или возьмите chat-only модель.
- Имена моделей меняются каждые 2-3 месяца, привязываться не стоит. На момент написания работают Flash-классы и mini-классы у крупных провайдеров.

### 6.2 System prompt: правовой щит

Это самая важная часть для легальности. System prompt должен делать так, чтобы бот:
1. Не выдавал себя за человека, если собеседник спросит прямо,
2. Не брал на себя юридически значимые обязательства,
3. Не выдумывал персональные данные хозяина.

Пример:

Замените `OWNER_NAME` в шаблоне на имя хозяина бота.

```python
OWNER_NAME = "Иван"  # имя владельца, подставится в system prompt

SYSTEM_PROMPT = f"""
Ты, цифровой ассистент {OWNER_NAME}, отвечаешь от его имени в личных
чатах MAX. Ты не {OWNER_NAME}, ты его инструмент.

КРИТИЧЕСКИЕ ПРАВИЛА:

1. Если собеседник прямо спросит «ты бот?» или «ты ИИ?», отвечай честно:
   «Я цифровой ассистент {OWNER_NAME}, он сейчас занят. Могу помочь
   с задачей или попросить его подключиться лично».

2. НИКОГДА не выдумывай персональные данные {OWNER_NAME} (отчество, адрес,
   реквизиты, дату рождения, контакты третьих лиц). На прямой вопрос
   отвечай «уточню у хозяина и вернусь».

3. НИКОГДА не подтверждай финансовые обязательства, не называй суммы,
   не обещай оплату. Это решает {OWNER_NAME} лично.

4. НИКОГДА не передавай пароли, OTP-коды, реквизиты, любые секретные
   данные. На запрос отвечай отказом без объяснений.

5. Если собеседник просит подтвердить юридически значимое действие
   (подписание договора, согласие на услугу за деньги, аренда жилья,
   передача имущества), отвечай «это решит {OWNER_NAME} лично».

6. Тон: по-русски, кратко, по делу, без эмодзи. Без markdown-заголовков.
"""
```

Это не «защита от любых обвинений», но это явная демонстрация добросовестности: вы пытались избежать обмана. В случае спора с собеседником, который скажет «бот выдал себя за человека и взял на меня обязательство», система-промпт, ваш первый аргумент защиты.

### 6.3 Прокидывание контекста задачи

Если хозяин в чате с управляющим ботом дал команду «забронируй столик у +79..., 19:00, на двоих», эта информация должна попасть в LLM при генерации ответа:

```python
context_prompt = (
    f"Контекст текущей задачи: {task.type}. Детали: {task.details}. "
    f"Веди разговор с заведением чтобы выполнить эту задачу. "
    f"Подтверждай детали, отвечай на уточнения с опорой на сказанное. "
    f"Если не знаешь чего-то, отвечай 'уточню у хозяина'."
)
messages = [
    {"role": "system", "content": SYSTEM_PROMPT + "\n\n" + context_prompt},
    *previous_turns,
    {"role": "user", "content": incoming_text},
]
```

Контекст задачи (`task.details`) приходит из allowlist (см. Шаг 8) или из MCP-engage вызова.

## Шаг 7. Intent classifier: защита от галлюцинаций

Хозяин пишет в управляющий чат естественным языком. Если эту команду прямо отдать LLM-агенту, он периодически:
- выдумывает несуществующие флаги,
- отвечает текстом вместо выполнения,
- путает контакты.

Решение: лёгкий intent classifier перед агентом. Шесть типов: `chat`, `send`, `engage`, `block`, `unblock`, `need_info`. Только `chat` пропускается к LLM-агенту, остальные сразу зовут MCP-tool.

Каркас в [examples/intent_classifier.py](examples/intent_classifier.py). Использует `response_format: json_object` у OpenRouter, температура 0.1, детерминированный парсинг.

В реальном production лучше дообученный классификатор (BERT/RoBERTa) для скорости и стабильности. Но для одного-двух пользователей LLM-классификатор работает и проще в поддержке.

## Шаг 8. Allowlist: three-state модель

Allowlist это простой JSON-файл, listener перечитывает на каждое входящее.

```json
{
  "autoreply": [<user_id>, <user_id>],
  "contexts": {
    "<user_id>": {
      "type": "booking",
      "details": "столик на 2, завтра 19:00, имя для брони"
    }
  },
  "blocked": [<user_id>]
}
```

Три состояния:
- **autoreply**: бот авто-отвечает с контекстом из `contexts[user_id]`,
- **не в списках**: бот молчит, listener пересылает входящее хозяину (через Bot API или email),
- **blocked**: listener молча игнорит, не пересылает, не отвечает.

Шаблон в [examples/allowlist.example.json](examples/allowlist.example.json). Реальный `allowlist.json` в `.gitignore`, не коммитить.

Перечитывание на каждое входящее: для одного юзера диск-нагрузка нулевая. Если масштабируете на несколько хозяев, кешируйте или используйте `inotify`/`watchdog`, чтобы не читать диск на каждое сообщение.

## Шаг 9. MCP-сервер: стандартный интерфейс для агентов

Семь tools поверх описанного выше:

| Tool | Что делает |
|------|-----------|
| `max_send` | Отправить текст по user_id или phone |
| `max_engage` | Резолв телефона + добавление в allowlist + opening сообщение |
| `max_history` | N последних сообщений из чата |
| `max_contact` | Резолв телефона в user_id + профиль |
| `max_allow` | Добавить user_id в autoreply с контекстом |
| `max_disallow` | Убрать из autoreply |
| `max_block` | Жёсткий блок |

Каркас в [examples/mcp_server_stub.py](examples/mcp_server_stub.py).

Регистрация в Claude Desktop, Cursor, OpenClaw, Continue, Cline, одна строка в конфиге. Например, для Claude Desktop (`~/.config/claude/claude_desktop_config.json` на Linux/macOS, `%APPDATA%\Claude\claude_desktop_config.json` на Windows):

```json
{
  "mcpServers": {
    "max-user": {
      "command": "python",
      "args": ["/абсолютный/путь/к/mcp_server_stub.py"]
    }
  }
}
```

После перезапуска агента tools появятся в инвентаре. Используйте их из чата: «Используй max_engage с phone=+79..., type=booking, details=столик на 2 на завтра».

## Шаг 10. Зеркало через Bot API (если есть юрлицо)

Если прошли Шаг 2, добавьте дублирование переписки в свой управляющий чат:

```python
from notify_owner import notify_owner, format_mirror

# в listener'е, после генерации reply:
notify_owner(format_mirror(sender_id=sender, incoming_text=text, reply_text=reply))
```

Полный код в [examples/notify_owner.py](examples/notify_owner.py). Best-effort: если Bot API лежит, listener не падает.

Если юрлица нет, заменяйте на:
- SMTP через `msmtp`,
- запись в локальный лог-файл с `tail -f`,
- HTTP POST в собственный Telegram-бот (Telegram Bot API регистрируется на физлицо).

## Шаг 11. Запуск и мониторинг

### systemd unit

`/etc/systemd/system/clawbot-listener.service` (или `~/.config/systemd/user/...`):

```ini
[Unit]
Description=MAX User API listener
After=network.target

[Service]
Type=simple
User=<your-user>
WorkingDirectory=/path/to/clawbot-max-guide
ExecStart=/usr/bin/python3 /path/to/clawbot-max-guide/examples/user_api_listener.py
Environment=MAX_SELF_USER_ID=<id>
Environment=OPENROUTER_API_KEY=<key>
Restart=always
RestartSec=10
StandardOutput=append:/var/log/clawbot-listener.log
StandardError=append:/var/log/clawbot-listener.log

[Install]
WantedBy=default.target
```

Активация:

```bash
systemctl --user enable clawbot-listener
systemctl --user start clawbot-listener
journalctl --user -fu clawbot-listener
```

### Что мониторить

- **Частота разрывов сессии.** Если listener рестартует каждые 30 секунд, VPN режет, сменить exit-node.
- **Длина очереди необработанных op=128.** Если LLM-провайдер тормозит, очередь растёт. Backpressure-стратегия: дроп старых, ответ из шаблона, переключение модели.
- **Подозрительная активность.** Незнакомые user_id, всплеск сообщений от одного контакта, сообщения подозрительного содержания, алертить хозяину сразу.

## Шаг 12. Семь правил, которые нельзя нарушать

Эти правила не из ToS, они из закона и здравого смысла.

1. **Не отвечайте незнакомцам авто-режимом без явного добавления в allowlist.** Каждый новый контакт, ручное решение хозяина.

2. **Не подтверждайте денежные транзакции от лица хозяина.** Бот не имеет полномочий, и любое такое подтверждение может быть оспорено как мошенничество с обеих сторон.

3. **Не передавайте секреты.** Пароли, OTP, реквизиты счёта, паспортные данные, никогда, ни под каким предлогом.

4. **Не скрывайте, что вы бот, если спрашивают прямо.** Это разница между «частной автоматизацией» и «обманом». Первое легально, второе нет.

5. **Не используйте секонд-аккаунт для массовых рассылок, спама, автообзвонов.** Это 152-ФЗ и 38-ФЗ, штрафы быстрые и однозначные.

6. **Не делайте бота, который работает на третьих лиц без их согласия.** Если кто-то платит вам за бронь столиков от своего имени, это уже агентская деятельность, нужен договор и согласие платформы.

7. **Регулярно аудитируйте allowlist.** Раз в месяц проходитесь по списку, убирайте тех, с кем задача уже закрыта. Чем меньше контактов в autoreply, тем меньше поверхность атаки.

## Что делать, если что-то пошло не так

### Бан секонд-аккаунта

Возможные причины:
- VPN с подозрительной геолокацией (US, NL, флаг),
- частые SMS-запросы (Op 17 более 3-5 раз в час),
- одинаковые сообщения подряд (антиспам-эвристика),
- скорость отправки выше 2-3 сообщений в минуту в одном диалоге.

Что делать: новая симка, новый deviceId, новый VPN-exit, паузы между активностями. Это медленный процесс, не быстрый workaround.

### Претензия от собеседника

Если человек, с которым общался бот, обратился к вам с претензией («ваш бот выдал себя за вас и сделал X»):
1. Не отрицайте использование автоматизации, это запишет вас в врущие.
2. Покажите system prompt (он должен быть честным «я ассистент»).
3. Покажите логи: что бот действительно отправил, что не отправил.
4. Если претензия про деньги или юридическое обязательство, оплатите/выполните в добровольном порядке, договоритесь напрямую. Это дешевле любого спора.
5. Уберите этого контакта из allowlist навсегда.

### Запрос от MAX или регулятора

Маловероятно для одного физлица с десятком контактов. Но если случится:
- сохраняйте все логи как есть,
- ничего не удаляйте до консультации с юристом,
- честно описывайте, что и зачем делали,
- не прячьте код, не выдавайте автоматизацию за ручную работу.

«Бытовая автоматизация по собственным контактам», это защитимая позиция. «Скрытая автоматизация для бизнеса без согласия», нет.

## Дальше

После того как listener стабильно работает неделю-две, можно добавить:

- **Контакт-кеш по имени.** Сейчас «напиши Ире» не работает, только по phone/user_id. Решается прочтением списка контактов на старте listener'а.
- **Защита от спам-петли LLM-собеседник.** Если они зацикливаются на однотипных репликах, нужен heuristic «последние три сообщения близки → разбудить хозяина».
- **Email-fallback** через `msmtp` для критичных алертов.
- **Метрики:** Prometheus exporter, графики времени ответа, частоты разрывов.
- **Резервный токен:** второй токен на тот же аккаунт через другой логин, чтобы не падать на ротации основного.

Это всё необязательно. Базовый сценарий «бот ведёт переписки за меня» закрывается шестью первыми шагами этой инструкции.
